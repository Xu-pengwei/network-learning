# 实验 06：Wireshark ICMP 抓包实验

实验日期：2026 年 11 月 2 日

## 实验目的

使用 Wireshark 观察 Ping 的 ICMP 回声请求和回复，学习通过地址、类型、标识符和序列号分析数据包。

## 实验环境

- VMware 中的 Ubuntu，Wireshark 4.6.4
- 抓包网卡：ens33
- Ubuntu 地址：192.168.168.128/24
- 测试目标：192.168.168.10

## 操作过程

1. 安装 Wireshark，允许 wireshark 用户组抓包，将当前用户加入该组并重新登录。
2. 在 Wireshark 中选择 ens33 并开始捕获。
3. 在 Ubuntu 终端执行：

```bash
ping -c 4 192.168.168.10
```

4. 停止捕获，使用 `icmp` 显示过滤器查看 ICMP 流量。
5. 分别使用 `icmp.type == 8` 和 `icmp.type == 0` 筛选回声请求和回声回复。

## 验证结果

终端测试结果：发送 4 个包，收到 4 个回复，丢包率 0%。重新抓包后观察到第 32、34、36、38 号为请求，第 33、35、37、39 号为回复。

以第 32、33 号包为例：

| 字段 | 第 32 号请求 | 第 33 号回复 |
| --- | --- | --- |
| 源地址 | 192.168.168.128 | 192.168.168.10 |
| 目标地址 | 192.168.168.10 | 192.168.168.128 |
| ICMP 类型 | 8（Echo Request） | 0（Echo Reply） |
| 标识符（BE） | 4983 | 4983 |
| 序列号（BE） | 1 | 1 |

Wireshark 显示第 32 号的响应为第 33 号，第 33 号的请求为第 32 号，响应时间约 0.862 毫秒。抓包已保存于 Ubuntu 本地。

## 遇到的问题

安装时提示 dpkg 被中断，按系统提示执行 `sudo dpkg --configure -a` 完成未结束的软件包配置后，重新安装 Wireshark。

首次筛选未看到本机 Ping 的请求和回复；重新开始捕获后再执行 Ping，观察到了完整的 4 组请求和回复。

## 总结

Ping 使用 ICMP 回声请求和回声回复测试连通性。可以结合源、目标地址以及标识符和序列号，将请求和回复配对。Wireshark 显示过滤器用于筛选显示内容，不会删除其他已捕获的包。

若只看到请求而没有回复，可检查目标设备是否开机、地址是否正确、网络连接、防火墙规则及抓包网卡和过滤条件；需要根据实际证据判断原因。
