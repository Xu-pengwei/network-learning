## 抓包方法

1. 在 Wireshark 中选择 `ens33` 开始抓包。
2. 使用以下显示过滤器：

```wireshark
tcp.port == 53 && ip.addr == 192.168.168.10
```

3. 在 Ubuntu 中主动连接服务器：

```bash
nc -vz -w 3 192.168.168.10 53
```

4. 停止抓包，确认所有相关报文属于 `tcp.stream eq 0`。
5. 将抓包保存为 `2026-11-08-tcp-handshake.pcapng`。

## TCP 三次握手

| 包号 | 方向 | 标志位 | Seq | Ack | 含义 |
|---|---|---|---:|---:|---|
| 99 | `192.168.168.128:33330 → 192.168.168.10:53` | SYN | 0 | 0 | 客户端请求建立连接 |
| 100 | `192.168.168.10:53 → 192.168.168.128:33330` | SYN, ACK | 0 | 1 | 服务器同意连接并确认客户端 SYN |
| 101 | `192.168.168.128:33330 → 192.168.168.10:53` | ACK | 1 | 1 | 客户端确认服务器 SYN，连接建立 |

三条报文的 Stream index 均为 `0`，地址和端口方向相互对应，因此属于同一次 TCP 连接。

## TCP 四次挥手

| 包号 | 方向 | 标志位 | Seq/Ack 变化 | 含义 |
|---|---|---|---|---|
| 102 | 客户端 → 服务器 | FIN, ACK | 客户端发送 FIN | 客户端请求关闭发送方向 |
| 103 | 服务器 → 客户端 | ACK | `Seq=1, Ack=2` | 服务器确认客户端 FIN |
| 104 | 服务器 → 客户端 | FIN, ACK | 服务器发送 FIN | 服务器请求关闭自己的发送方向 |
| 105 | 客户端 → 服务器 | ACK | 确认服务器 FIN | 连接关闭过程完成 |

包 103 不是三次握手的第三个报文，而是四次挥手中对客户端 FIN 的确认。

## 序列号与确认号

Wireshark 默认显示相对序列号，因此本次主要看到 `0`、`1` 和 `2`。

- SYN 即使不携带应用数据，也会占用一个序列号。
- 包 99 的 `SYN, Seq=0` 被服务器收到后，服务器通过包 100 的 `Ack=1` 表示下一次期望收到序列号 1。
- FIN 同样会占用一个序列号，因此客户端发送 FIN 后，服务器的确认号继续增加。
- 普通且不携带数据的 ACK 本身不额外占用序列号。

## 知识点总结

- 三次握手：`SYN → SYN, ACK → ACK`。
- 四次挥手通常为：`FIN, ACK → ACK → FIN, ACK → ACK`。
- TCP 通过四元组识别连接：源 IP、源端口、目标 IP、目标端口。
- 临时端口 `33330` 由客户端使用，服务器服务端口为 `53`。
- `tcp.stream` 可帮助筛选同一次 TCP 会话。
- 三次握手完成后，双方才确认彼此的发送与接收能力。
- SYN 和 FIN 各占用一个序列号，即使其 TCP Segment Len 为 0。
